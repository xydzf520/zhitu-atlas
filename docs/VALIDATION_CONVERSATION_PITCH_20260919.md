# 沟通中心 AI 匹配话术验收

> **历史版本记录**：正文只描述文内日期和版本。功能、测试数、路径及回滚命令不代表当前版本；现行操作见 [使用指南](USER_GUIDE.md) 和 [运行与升级](OPERATIONS.md)。原有测试结论保留，不追认为本轮复测。

版本：0.17.4+atlas.13.7；日期：2026-09-19。

## 使用路径

沟通中心 → 选择联系人 → AI 话术与回复 → 岗位匹配话术 → 生成岗位匹配话术。

- 无需等待招聘者发来文本；关联多个岗位时先选择本次沟通的岗位。
- 根据完整 JD、本人已确认经历和最新 20 条已采集文本消息，选择相关经历生成话术，复用匹配招呼与独立审校 Agent。
- 编辑和复制后自行核对使用；生成或复制不创建发送指令，不解除发送暂停。
- 点击「完整查看话术与依据」展开文案、JD 要求、经历原文、匹配关系及待核实项。
- 原有常规回复和主动跟进保留在「回复对方 / 跟进」。

## 数据与保护

后台只接受账号、联系人、关联岗位 ID 和依据版本，从统一存储读取内容，不接受前端替换的 JD 或履历。公司名缺失时，仅通过同账号同会话的可靠岗位 ID 关联补用会话中的公司名，返回字段来源；不按相似名称合并。公司／岗位名称与 JD 缺失分别提示。

只使用已确认经历；要求原文和经历引用必须能逐字核对，数字口径不允许改写为无依据的业绩，独立模型审校事实与相关性。不匹配时说明缺口，不回退通用模板。

缓存绑定账号、联系人、岗位内容、资料版本、会话文本、模型及 Agent 提示词。调用前验证依据版本，完成后再次核对；生成期间资料或消息改变则拒绝旧结果。切换会话不串稿，生成期间本人编辑优先；草稿按账号＋联系人＋岗位保存在当前浏览器 sessionStorage。

## 检查结果

- 236 项回归测试通过，覆盖无招聘者回复、确认经历限制、伪造 JD、账号隔离、无关岗位、多个关联岗位、缓存与新消息失效、证据不足，以及 DOM 详情缺少公司名的真实数据形态。
- 原沟通中心 15 项交互检查通过；新增匹配话术 10 项交互检查通过，覆盖迟到结果、编辑保留、依据展开、完整阅读窗口、旧版本提示和不调用发送接口。
- Node / Vue 类型检查、SQLite 插件、网页和 Electron 正式构建通过。保留现有 chunk 体积提示。
- 核对 1280×720 和 1920×1080 界面；完整阅读窗口采用单层内容滚动。

真实模型验收已完成：使用实际已登录账号的一条关联岗位，CommandCode `deepseek/deepseek-v4.1-flash` 生成 191 字、1 条匹配证据的话术，写作与独立审校共 2 次模型调用；四项审校标记均通过，共计 23,178 tokens。生成结果保留为草稿，没有发送消息，自动发送仍暂停。详细个人文案仅存本机 `artifacts/conversation-pitch/live-check.json`，未提交仓库。

隔离 UI 用受控模型结果测试交互，不冒充真实模型调用。后续 13.8 将此处“完整查看”的交互升级为自动弹出本人确认窗口，见对应版本验收。
