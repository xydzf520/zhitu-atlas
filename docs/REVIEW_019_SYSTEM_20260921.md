# 职途 Atlas 0.19.0 系统评审与改进顺序

审查日期：2026-09-21。对象：当前源码、已安装的 0.19.0 及本机运行数据。

本次交付是分析与复现记录，不是功能修复发布。没有修改产品代码、模型配置、简历、额度或发送授权，没有调用付费模型、发消息或刷新 BOSS 页面。边界复现在独立临时数据库完成，结束后清除测试数据。

后续状态：上述七类复现问题已在 0.19.1 修复并完成回归与本机安装，见 [修复验收记录](SYSTEM_FIXES_0191_20260921.md)。下文保留当时审查结果，后续产品建议不等同已完成。

## 总体判断

当前已有从资料、岗位、匹配到沟通和进展的主要模块，也有事务、版本检查、发送核验和备份基础。下一步应优先提升**判断准确、任务不中断、操作有落点、结果能核实**。现阶段适合完善现有内核，不需要改成分布式服务或更换 SQLite。

此前 310 项回归和 47 项原生隔离检查通过，说明已有用例通过；本次复现了未覆盖的边界，不能据测试数量推断功能不存在缺陷。

## 已复现的具体问题

P1 表示应先修复的判断、归属或执行问题；P2 表示统计、体验与效率问题。这里没有把隔离测试缺陷描述为已经发生的真实误投递。

| 优先级 | 触发与实测结果 | 影响 | 建议修复与验收 |
| --- | --- | --- | --- |

| P1 | JD 同一句写“3 年产品经验及 2 年团队管理经验”，仅确认 10 年产品经验，整个年限项就判满足 | 基础检查漏掉独立管理条件，仍需后续 AI 检查兜底 | 拆成两个独立要求，分别关联证据；没有管理年限只能待核实，不可用总工龄替代 |
| P1 | 当前账号 A 的机会详情出现账号 B 的同名合并候选；跨账号合并接口接受操作 | 切换账号后可能混合阶段、联系人和面试记录 | 统一 AccountScope，详情、候选、关联、归档、合并和汇总都验证账号；跨来源实体关联与合并原始记录分开。当前真实数据未发现已发生跨账号合并 |
| P1 | 修改“市场研判”提示词，会把排队的“沟通话术”任务标为过期 | 无关编辑打断工作，需要重新创建任务 | 为每类任务声明依赖 Agent、资料字段和策略；无关 Agent 修改不影响任务，实际依赖变化仍中断 |

## 从求职结果组织下一轮功能

| 环节 | 现有基础 | 优先补齐 |
| --- | --- | --- |
| 简历与资料 | 一份资料、确认依据、资格事实及版本 | 公司—任职—项目—成果结构化关联；正文与证据的差异清单；导出版本和 BOSS 版本单独核验 |
| 岗位获取 | 搜索、推荐、浏览、文件导入及去重 | 按渠道显示新岗位、重复、缺 JD、职位失效与采集失败；按现有候选覆盖决定补采，避免重复刷岗位 |
| 匹配判断 | 基础规则＋AI 分析＋确认经历＋执行检查 | 条件逐条拆解，显示具体缺什么；按目标岗位族选相关证据，避免一个关键词分数覆盖所有产品方向 |
| 今日执行 | 任务队列、限额、冷却、发送回读 | 给出可执行的今日清单：补详情、核实事实、分析、准备联系、处理回复；每项能直接打开对应记录 |
| 沟通 | 同步、话术、审校、确认、企业研判 | 优先展示对方最新问题及建议下一步；先回答当前问题，介绍经历按相关性展开，避免每次长篇自荐 |
| 企业理解 | 公开搜索、主体候选、JD 与回复来源 | 区分企业事实、招聘者说法和模型推测；显示新回复改变了哪条判断及依据，主体不明先核实 |
| 面试与结果 | 阶段、面试轮次、Offer 与待办 | 把准备问题关联到具体经历卡；待办有到期入口；仍不将索要简历当面试、不将聊薪当 Offer |
| 复盘 | 有首次联系批次与后续阶段统计 | 分开今日动作、当前库存、同批转化；按岗位族／渠道／简历版本比较，有样本不足提示，不归因于招聘者人格或简单“话术有效” |

资料应从 HR 的“时间线、职责层级、资格与材料一致性”和业务部门的“业务问题、本人决策、交付与结果证据”组织。最终材料可以按岗位选择相关案例，但不能改变事实、把工具使用等同算法能力或把项目规模等同本人贡献。私有匹配字段与对外简历字段应分别控制，例如学历可仅用于匹配，不自动加入导出正文。

## AI：从长报告转为可执行结论

1. **分层分析。** 程序先做去重、时效、城市、薪资与确定性条件；岗位族汇总再选择代表性 JD；只有值得投入或边界不清的岗位进入深度分析。保留样本数量与选择依据。
2. **控制输入重复。** 当前全局输入在 sources、confirmedEvidence、projects 中多处提供相关资料；统计全量保留，长文本按证据 ID 组织，工具按需读取。最近 60 个岗位可改为按方向、公司和需求分层选样，避免同类 JD 占满。
3. **区分实时准备与长分析。** 当前任务工作器和模型租约均串行。可先完善排队时间和优先级，再增加受控模型并发；浏览器及发送仍按账号串行。不能通过同时开多个任务绕过预算。
4. **按用途设置预算。** 为简短话术、逐岗分析、全局研判提供可选择的输出与时间预算，调用前提示是否收费、缓存或预计长任务。保留用户现有 max 配置，未经选择不偷偷降低。
5. **贯通调用结果。** 现有 Agent 页已明确写“模型已返回”，不是“业务已通过”；还应串联 taskId、modelCallId、validationResult 和 artifactId，方便定位“模型返回但引用校验失败”，并分别统计服务响应与业务可用率。
6. **质量基准集。** 增加可公开的合成 JD／简历／会话样本，覆盖 AND／OR、缺事实、提示注入、混淆来源、硬条件与礼貌拒绝；统计误排、漏核、无依据引用、合格草稿率及每份可用结果的用量。人工评分是评测标签，不是录用概率。

全局需求矩阵目前按要求原文字符串分组，同一能力的不同表述容易分成多行。可建立可解释的能力标签与别名，原文和证据始终可展开；未确认能力不得因标签相似而自动满足。

## 显示与交互

| 页面 | 默认看到什么 | 操作必须落到哪里 |
| --- | --- | --- |
| 全景总览 | 今日待办、需要本人处理的阻塞、真实进展、地区分布 | 对应机会或会话，不跳到泛列表后再找 |
| 全局分析 | 3 个主要结论、最关键改进、样本与证据覆盖 | 精确筛选、资料字段、待核实项；“缺 JD 25 个”应直接打开这 25 个 |
| 机会发现 | 值得看／待核实／可联系／执行中／结果 | 岗位详情、失败原因与下一步；清楚区分初筛满足和允许发送 |
| 沟通中心 | 未处理消息、当前会话、短回复草稿 | 招聘者原文、相关岗位、事实依据及确认状态 |
| 企业与进展 | 当前阶段和下一事件 | 轮次、日程、附件版本及结束原因 |
| 简历与资料 | 当前对外版本、待核对差异、经历结构 | 对应公司／项目／指标；专业参数按需展开 |
| 任务／Agent／设置 | 在工具区集中放置 | 仍保留明确直达入口，避免与日常动作争抢注意力 |

现有全局改进建议主要只跳到资料页或发现页，没有携带完整待处理对象；地区图也通过文字搜索跳转，不是精确城市过滤。“地点待核实”当前会变成空查询，无法直接看到对应未知地点集合。应统一可复用的筛选对象和可分享路由。

继续保留日间模式、系统字体、单层滚动和长文折叠。少量关键图表配列表即可，不添加没有可信量化依据的雷达分数或成功率。

## 数据、稳定性和开源准备

- **保留 SQLite。** 当前业务库约 4.5 MiB，不构成更换数据库的依据。0.18.2 已有分析正文去重、派生查询和分块备份；继续对热点统计做增量更新，并评估缓存失效后重建成本。
- **先明确领域边界。** 资料事实、岗位来源、匹配评估、消息动作、阶段结果分别服务化；统一 ID 与状态契约。不要为拆文件而制造多个重复写入入口。
- **拆分大页面。** 当前 Dashboard 约 1,644 行、BossInbox 约 1,231 行、Discovery 约 1,010 行；优先按会话、详情、筛选和执行状态拆组件与 composable，并补接口行为用例。
- **输入和诊断。** 通用 RPC 仍允许 64 MiB 请求；备份已经分块，应按接口设置更小的业务上限和并发限制。队列轮询错误目前被静默吞掉，补可读错误码、连续失败计数和恢复状态，不记录密钥与完整简历。
- **连续运行验收。** 补 8 小时采集／同步／模型等待／页面切换，观察常驻内存、监听器、队列恢复；基础负载通过不能代替长时运行。
- **同步覆盖。** 保留当前“本轮可读取范围”的表述；补历史断点、缺失字段和失败对象直达，不能把页面不再返回新消息当作平台完整历史已读完。
- **发布边界。** 全国适配需继续补区县冲突样本；不同城市的平台实测、Windows／macOS、猎聘实时接入仍需各自验收。公开仓库前的隐私、许可证与依赖来源专项检查不在本次已完成范围。

## 推荐实施顺序与门槛

| 批次 | 改动 | 验收门槛 |
| --- | --- | --- |
| A：判断与归属 | 修复学历／年限、城市冲突、跨账号机会操作、导入分析统计 | 本文边界全部转为回归；未知条件仍待核实；不改变发送额度与授权 |
| B：执行连续性 | 按任务依赖拆版本、链接与匹配分层失效、排队诊断 | 无关编辑不打断任务；实际依据变化必拦截；缓存与重启不导致重复发送 |
| C：求职行动 | 今日清单、精确筛选、资料差异和岗位族准备 | 每个统计／建议可以到具体对象并完成处理；对外简历和本机事实保持可追溯 |
| D：AI 与发布 | 代表性采样、用途预算、质量评测、连续运行及真实平台验收 | 记录每份可用结果的耗时和用量；合适真实岗位验证回读，不发测试消息充数 |

最先交付 A＋B；随后从现有岗位中挑选少量值得投入的真实候选，补齐当前分析及阻塞，再按本人授权启动。当前 20 条自动消息／10 次首次联系等原有规则保持不变，不因审查自行扩大额度。
