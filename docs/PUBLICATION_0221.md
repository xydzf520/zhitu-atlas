# 0.22.1 公开源码检查

核对日期：2026-09-22。范围为准备发布的源码快照、中英文 README 和公开仓库提交；不是独立安全审计，也不是对所有历史版本的无条件保证。

## 公开范围

- README 主动公开作者姓名、职业概要、上海求职方向、GitHub 作品和微信。这些内容由作者授权用于求职交流。
- 保留版权署名、第三方许可证原文及上游来源说明。许可证中的第三方作者邮箱属于原始署名，不替换为项目联系人。
- 不公开完整简历、教育与联系方式档案、真实招聘对话、求职数据库、简历附件、Cookie、密钥、本机绝对路径或私有服务器地址。
- 测试与文档中的业务数值改用虚构样例，不能拿来代表作者的真实履历或产品成效。

## 核查方式

1. 枚举当前源码，检查凭据模式、私有文件类型、链接与二进制文件。唯一项目二进制资源为应用图标。
2. 另行检查邮箱、手机号、主目录路径、内网地址、公司标识和履历数字；逐项区分许可署名、公共服务、虚构测试与私人信息。
3. 使用独立的源码导出，不复制 `.git`、构建产物、依赖、`artifacts`、运行目录或凭据。
4. 从公开快照建立新提交，提交作者使用 GitHub 的 noreply 地址；旧私有历史不进入公开仓库。
5. 运行源码／历史检查，并验证脱敏后的话术、事实口径与未确认经历拦截测试。
6. 发布后回读远端源码与提交信息，核对公开文件清单和内容。

旧开发仓库存在已经删除的地图对象。公开新历史只包含审查后的当前源码，保留来源与许可说明，不将“删除旧历史”描述为消除了第三方权利。

## 验证证据

0.22.1 发布基线已通过 503 项测试、Node／Vue 类型检查、生产构建和隔离客户端安装；范围与未验证事项见 [独立分发记录](DISTRIBUTION_0221.md)。本次脱敏改动的 106 项话术与沟通测试通过，日志保存在本机忽略提交的 `artifacts/github-publication/`。

规则扫描只能识别已覆盖的模式，不能证明不存在任何未知敏感信息。公开仓库的业务测试全部使用隔离数据，不连接作者的 BOSS 账号，不发送真实测试消息。
