# 运行、升级与排错

适用：**0.22.1 · Linux**。命令在 Atlas 项目根目录执行。

## 运行方式

| 方式 | 如何使用 | 生命周期 |
| --- | --- | --- |
| 已安装桌面 | 从应用菜单打开「职途 Atlas」 | 桌面启动其后台与内置浏览器；退出桌面停止原生 BOSS 操作 |
| 源码桌面 | 安装依赖、`pnpm build`、`pnpm start` | 与打包版使用相同默认数据目录，不应拿真实目录做开发实验 |
| 本机网页 | 桌面启动后打开 `http://127.0.0.1:5178/desktop.html` | 关闭网页不等于暂停后台任务 |
| 独立网页服务 | 构建后 `pnpm web` | 由终端管理进程；没有桌面时不能执行 BOSS 浏览器操作 |

源码环境使用 Node.js 22.13+、pnpm 8.15.9；完整客户端已包含 Electron。依赖下载需要网络。若安装时显式忽略了脚本，应确认 Electron 运行时已安装后再打包。

`pnpm dev` 提供桌面开发入口。仅打开 Vite 5179 不会启动独立业务服务，也不能替代正式网页。桌面和独立网页后台都使用 5178；端口占用时先识别是哪个进程，不要用反复刷新 BOSS 或删除数据库来处理。

## 数据目录

| 内容 | 默认位置 |
| --- | --- |
| 业务库 | `~/.local/share/zhitu-atlas/storage/atlas.db` |
| 地图配置 | `~/.local/share/zhitu-atlas/private/maps.json`；不进入业务备份 |
| 模型配置 | `~/.local/share/zhitu-atlas/private/models.json` |
| 本机服务信息 | `~/.local/share/zhitu-atlas/storage/atlas-runtime.json` |
| 附件 | 数据根下 `attachments` 或版本化恢复目录 |
| 桌面 session | `~/.local/share/zhitu-atlas-desktop/` |
| 安装与版本 | `~/.local/share/zhitu-atlas-app/releases/`，`current` 指向当前完整版本 |
| 桌面菜单项 | `~/.local/share/applications/zhitu-atlas.desktop` |

`ATLAS_DATA_ROOT` 可指定独立业务目录，桌面 userData 对应为该路径加 `-desktop`。可同时设置 `ATLAS_PORT=5188` 使用独立回环端口（1024–65535）。测试与开发使用独立数据目录和端口，无需关闭生产客户端。

## 构建与安装完整包

```bash
pnpm install --frozen-lockfile
pnpm check
node scripts/atlas-package.cjs artifacts/releases/atlas-linux
```

输出目录必须尚不存在。打包读取锁定的 Electron 运行时及构建产物，输出完整目录、清单 `manifestSha256` 和归档 `archiveSha256`。安装传入的是**清单哈希**。

完整包用户可直接执行 `./start.sh`，或退出客户端后执行 `./install.sh` 安装到应用菜单；两者无需另装 Node.js。安装脚本读取包内清单哈希，下载包的真实性仍需对照发布渠道单独提供的 SHA256SUMS 核验。

维护者也可使用下面的 Node 安装入口；把引号内的说明替换为打包输出的实际 64 位清单哈希：

```bash
ATLAS_RELEASE_HASH='替换为实际的 manifestSha256'
node scripts/atlas-install-release.cjs artifacts/releases/atlas-linux "$ATLAS_RELEASE_HASH"
```

安装器检查逐文件内容、架构、路径和符号链接，使用安装锁和 `current` 原子切换；保留旧发布目录并更新新桌面菜单。它不自动启动程序，不会主动重设现有业务策略。`scripts/atlas-install.cjs` 是归档级兼容工具，不是当前完整发行包的首选安装方法。

旧版本记录中的哈希只适用于当时的包，不能用于另一次重新构建的文件。当前通用版验证记录见 [0.22.0 验收](GENERAL_RELEASE_022.md)。

## 三种容易混淆的迁移

| 操作 | 数据与凭据 | 自动执行 |
| --- | --- | --- |
| 同机首次从旧目录升级 | 只读复制 `~/.geekgeekrun/` 的配置、数据库和附件到新目录；本机模型凭据保留，浏览器配置独立，可能需重新登录 | 首次迁移后暂停，见下文 |
| 跨电脑的加密备份恢复 | 包含业务数据、资料版本、设置、历史及附件；不携带平台 Cookie、模型 API 密钥或运行租约 | 恢复后暂停，重新配置凭据、登录并检查 |
| 已使用新目录后的普通程序升级 | 使用原有新目录，不再次覆盖迁移，不替换用户数据 | 保留已有策略，不保证自动暂停 |

第一行的执行状态：首次目录迁移会暂停自动任务与发送，关闭自动回复和自动采集设置，清除运行租约；发送中记录转为待核实。原目录保留，已有新目标目录不被覆盖。源后台仍在运行、数据库损坏或迁移失败时，不覆盖原数据。

同机保留的原始备份和迁移副本含私人资料及配置，应保留在本机；它们与界面导出的脱敏加密迁移包用途不同。旧目录不会因迁移被自动删除或改写。

## 备份、恢复与回滚

在「设置 → 数据管理 → 加密备份」设置至少 10 位密码，生成备份。密码不随文件保存。恢复前预览内容，先导出当前数据，再确认替换；恢复会替换业务数据，不是自动合并两台电脑的数据。

0.18.2 默认生成 V2 分块加密备份：业务库一致性快照加托管附件，原始数据总量上限 512 MiB，传输文件上限 514 MiB，单附件上限 15 MiB。每块校验加密认证，整个文件还校验清单、顺序及 SHA-256；旧 V1 文件仍可预览和恢复。浏览器下载仍需组装 Blob，大备份需留出足够内存。导出完成提示代表已发起下载，请确认文件实际保存。

「设置 → 数据管理 → 存储管理」可以查看占用、校验数据与引用。整理只回收没有任何现存记录引用的 AI 正文和超过 24 小时且未使用的备份临时文件，不清理聊天、发送凭据、资料版本或业务历史。库内空闲页留给后续写入复用，不在运行中自动做全库 VACUUM。构建产物和安装回滚包单独管理。

备份包含托管附件目录内的附件，不会自动收集下载目录中的每一个 Word 文件。更换电脑后需重新配置模型凭据、登录 BOSS、核对任务，再明确启动。

程序回滚：退出客户端，使用上一版完整发布目录和其清单哈希运行同一安装器，切回旧版本。**程序回滚和数据恢复是两件事**；当前安装器不承诺旧代码能够读任意未来 schema。没有 schema 兼容证据时，保留当前备份，在独立目录验证，避免直接让旧版写新库。

**0.19.0 / 0.18.2 使用 schema 6；0.18.0／0.18.1 使用 schema 5。回退这两个版本必须停机并恢复升级前的完整数据备份，不能把新版库直接交给旧程序。** 先保留新版当前数据，以免丢失升级后新增记录；恢复到独立目录核对后，再成对切换程序与数据。

返回 0.18 以前的程序使用当时保留的旧安装及旧数据目录；此时新版本新增资料不会自动出现在旧库。具体本机备份位置见 [当次迁移记录](VALIDATION_INDEPENDENT_20260921.md#重复验证与回滚)。

## 验证方法

```bash
pnpm check
node scripts/atlas-native-checks.cjs artifacts/native-checks
node scripts/atlas-package.cjs artifacts/releases/check-release
node scripts/atlas-runtime-check.cjs artifacts/releases/check-release artifacts/client-check
node scripts/atlas-integration-benchmark.cjs
```

前两类测试使用隔离数据；原生检查需要 Linux 图形会话，以本地 HTTPS fixtures 替代 BOSS。完整客户端检查需要空闲的 5178、9338 端口，以及测试用 Chrome，默认 `/usr/bin/google-chrome`，可用 `CHROME_BIN` 指定。脚本会启动隔离桌面并测试后台退出恢复；不要对生产数据目录做这类破坏性检查。

这些命令不会给真实招聘者发送消息。设置中的「测试生成与工具调用」则会使用已保存模型并产生实际额度消耗，两者需区分。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| 启动失败／5178 占用 | 先确认是否已有 Atlas 或独立网页后台；同一业务目录桌面会尝试复用。退出不需要的实例后再启动 |
| 网页显示“服务未启动” | 确认桌面或 `pnpm web` 在运行，使用正式地址；不要以 Vite 资源页代替 |
| BOSS 在别的浏览器已登录，工作台仍未登录 | 在桌面 BOSS 工作台登录；不同浏览器会话不自动共享 |
| 账号已登录但岗位／消息缺失 | 看任务中心的同步覆盖、账号归属、详情和历史读取情况；打开对应页面核对，不能把缺失当作同步成功 |
| 任务不发送 | 查看全部自动任务暂停、发送暂停、经历确认、硬条件、分析时效、时段、额度和授权等具体原因 |
| 只有平台默认招呼 | 查看冷却及个性化说明状态；未核验匹配说明不算自动联系完成 |
| 发送结果不确定 | 到结果记录核实，不反复点击启动；确认未发送后仍需明确重新排队 |
| 模型 401／403／429 | 分别检查凭据、模型权限／套餐、额度／限流；保留草稿后手动重试，不连续重放未知结果 |
| 地图点位缺失 | 区分无地址、只有行政区、坐标系不明；没有精确坐标时按区域展示 |
| 安装提示锁存在 | 确认没有安装进程后再处理该安装目录的锁；不要删业务库或运行中的数据库文件 |

诊断时提供版本、入口、任务 ID 和脱敏错误即可；模型密钥、Cookie、完整简历和聊天原文不应进入项目问题报告。

## 对外提供源码

运行 `node scripts/atlas-source-export.cjs artifacts/releases/atlas-source`，得到不含 Git 历史、依赖、构建产物或用户资料的源码快照及文件清单。该快照无需 `git init` 即可安装依赖并构建。不要直接公开旧仓库全部历史，其中仍有已移除的地图资产。源码包、完整客户端包和校验值应分别提供。
