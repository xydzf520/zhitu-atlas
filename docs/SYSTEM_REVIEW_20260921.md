# 职途 Atlas 系统审查与优化

日期：2026-09-21。审查基线：独立内核 0.18.0；本轮源码与 Linux 发布包：**0.18.1**。

## 结论

项目已具备本机求职工作台的主要链路：岗位发现、账号隔离与去重、证据匹配、话术、发送核验、沟通、面试与结果记录。最需要改善的是**执行依据的一致性、对外表述的可信度、用户每一步该做什么**。更多菜单或更长的 AI 报告不能直接解决这些问题。

本轮完成下述内核、模型及交互改动，保留原有筛选门槛、发送限额与重要事项确认规则。没有修改真实简历、确认经历、模型凭据或启动自动联系。真实平台发送仍未在本轮验收；隔离测试通过不能代替它。

这是按代码路径、业务数据结构、自动化回归与隔离界面进行的系统审查，不是形式化安全证明，也没有用虚构的百分制为软件质量或录用概率打分。

## 从招聘过程重新组织产品

HR 与业务负责人可能参与相同环节，不能预设每个人的职责或心理。下面是求职准备的三个视角，而非对具体招聘者的心理推断。

| 视角 | 需要解决的不确定性 | 产品应帮助你做到 |
| --- | --- | --- |
| HR／招聘沟通 | 基本条件是否合适，履历是否一致，材料是否完整 | 对照地点、薪资、必要资历，明确未知信息与使用的简历版本 |
| 业务负责人 | 是否理解业务目标，能否承担任务，成果是否可信 | 用一项相关案例说明背景、本人行动、结果、证据与边界 |
| 求职者本人 | 岗位是否值得投入，双方是否真正适合 | 主动确认业务优先级、职责范围、协作关系和成果口径，再决定下一步 |

这套设计采用与岗位相关、以证据组织判断的原则。CIPD 的招聘甄选资料强调明确、客观的标准与结构化评估；OPM 将结构化面试建立在岗位相关能力及过往行为等信息上。上述来源支持准备方法，不证明这个 UI 会提高某个固定比例的录用率。[CIPD：甄选方法](https://www.cipd.org/uk/knowledge/factsheets/selection-factsheet/)、[OPM：结构化面试](https://www.opm.gov/policy-data-oversight/assessment-and-selection/structured-interviews/)。

产品设计推论：减少阅读负担，先说明岗位关联，再提供可追问的证据；给对方一个具体、容易回答的问题。这里不使用年龄、性别、头像或未回复时长去推断性格和录用意向，也不生成未经验证的“成功率”。

## 逐环节审查

| 环节 | 当前已具备 | 本轮处理／剩余边界 |
| --- | --- | --- |
| 个人资料 | 正文、经历证据、匹配资历、项目关联与版本 | 发现和执行使用已确认依据；正文与证据分别编辑，仍需做相互差异提示 |
| 获取岗位 | 搜索、推荐、浏览、文件导入；保留来源 | UI 明示当前自动采集城市为上海，不把可编辑城市等同多城采集能力 |
| 去重与归属 | 平台＋账号＋来源 ID；招聘者首次介绍去重 | 名称相似不自动合并；历史账号不明不能混入当前账号统计 |
| 匹配 | 硬条件、规则初筛、AI 建议、确认依据共同判断 | 增加必要条件与证据卡，矩阵与摘要共用核实状态计算；不存在证据或过期报告不能显示为已确认成果 |
| 首次联系 | 按 JD 和履历生成、独立审校、额度与冷却、回读 | 保留真实核验门槛；开聊不等于简历投递，生成不等于发出 |
| 常规回复 | 分类、上下文、自动／人工边界 | 新增独立语义事实审校，拦截没有数字但虚构职责或能力的内容；明确婉拒停止自动自荐 |
| 企业理解 | 公开搜索、来源、JD 与会话研判 | 可辅助准备问题，公开网页和招聘者说法不能自动成为已核实事实 |
| 面试准备 | 岗位、已确认经历、会话与轮次 | 区分本人／招聘方发言，隔离账号与平台；轮次变化使准备缓存失效；输出 HR、业务、本人反问三类问题 |
| Offer 与复盘 | 阶段历史、面试记录、Offer 字段和同批联系统计 | 手工阶段不是平台凭据；未知待遇不补全；样本少时不做策略因果归因 |
| 运行与恢复 | SQLite、租约、幂等任务、备份、生产构建 | 本轮加强排队依据与取消；仍需真实 BOSS、连续运行和完整升级启动的独立验收 |

个人表达建议：保持一份事实母版，针对 AI 平台／Agent、增长与 C 端、复杂产品交付三类岗位，分别选最相关的证据。工具名称作为实现手段，核心仍是解决了什么问题、本人承担什么、结果如何核对。不要把不同公司项目串成一段，也不要把近期 AI 项目当成全部个人优势。系统本轮没有替用户改写这些事实。

## 已修复的问题

| 优先级 | 原问题与影响 | 实现 |
| --- | --- | --- |
| P1 | 默认提示词升级未必使旧缓存失效，旧分析可能继续进入执行 | 所有 Agent 包括默认提示词都参与指纹；所有模型渠道配置参与缓存身份 |
| P1 | 任务排队期间资料或规则变化，可能按旧请求生成新资料的内容 | 创建时绑定资料、策略相关字段、模型与提示词；派发前不一致则中断，未调用模型 |
| P1 | 回复只检查数字和证据 ID，不能充分识别无数字的虚构能力 | 非空新 AI 回复新增独立事实、相关性、简洁性与承诺审校，失败不输出可自动发送的新回复 |
| P1 | 面试上下文缺少发言方向或轮次变化检查 | 只取正确账号／平台的最近文本，标注本人和招聘方；轮次、岗位或会话中途变化拒收旧结果 |
| P1 | 模型已连接但长时间无流输出时取消可能仍被读取阻塞 | 取消信号主动取消流 reader，读取返回后再次检查取消 |
| P2 | 自动队列靠前时手动任务长期等待 | 在尚未开始的队列中优先手动；运行中请求不抢占，明确显示两类等待数量 |
| P2 | 调度存储异常可能留下进程内 busy 状态 | 获取租约失败及释放阶段均确保 busy 清理，派发异常不形成未处理 Promise 拒绝 |
| P2 | 明确拒绝信息含 AI 关键词时可能进入自荐路径 | 分类先识别明确婉拒／关闭岗位，与沟通状态标签共用规则 |
| P2 | 推荐、矩阵与长报告堆在一起，操作过程占用大量页面 | 按需展开策略、统计漏斗、执行记录、成果案例、证据矩阵；保留关键额度、状态和异常；增加三类快捷定位 |
| P2 | 快速切换机会筛选时被正在加载的请求忽略 | 保留最新一次查询意图，丢弃旧条件响应，页面离开后不继续补发列表查询 |
| P2 | 历史任务结果容易误认为当前结论 | 标明执行时快照；资料／策略／模型／提示词变化时标记过期，原结果保留；岗位和会话仍需回业务页核对 |
| P2 | 任务中心的联系、核验步骤永久显示等待 | 读取当前账号真实联系任务数，区分当前采集轮次与联系库存，不显示虚假百分比 |

主要实现入口：[任务队列](../packages/ui/src/main/features/atlas-task-queue.ts)、[提示词版本](../packages/ui/src/main/features/atlas-agents.ts)、[回复与面试准备](../packages/ui/src/main/features/atlas-assistant.ts)、[模型传输](../packages/ui/src/main/features/atlas-model-transport.ts)、[沟通与证据规则](../packages/ui/src/common/hiring-guide.ts)、[提示词](../packages/ui/src/common/agents.ts)、[用人视角组件](../packages/ui/src/renderer/src/components/career/HiringBrief.vue)。

常规 AI 回复现在通常有“生成＋审校”两个付费阶段，工具续轮还可能增加请求数；各自记录用量。命中缓存不重复调用。界面派生的用人视角、证据卡及下一步规则不额外调用模型。旧报告因版本变化失效后，重新分析会产生用量，不应自动刷新全部历史报告。

## 下一批最值得继续的优化

| 优先级 | 事项 | 为什么／验收方式 |
| --- | --- | --- |
| P1 | 真实 BOSS 完整联系验收 | 选本人确实想联系、经历和资格已确认的岗位，核对默认招呼、定制文字、会话和消息 ID；不发测试消息充数 |
| P1 | 模型执行通道分工 | 目前单模型租约仍可能让长分析阻塞沟通准备。先记录排队时长，再设计受控并发、成本预算与取消；平台动作继续串行 |
| P1 | 调度错误诊断 | 将重复派发／心跳故障形成可读诊断、连续失败计数和恢复状态；当前派发重试避免崩溃，但诊断颗粒度不足 |
| P1 | 简历正文、证据与平台版本差异 | 保存时显示哪些表述不同，平台保存后回读核对；不因本地保存就宣称 BOSS 已同步 |
| P2 | 列表查询下推到 SQL | 机会和部分会话查询仍全量读取／排序；当前容量测试达标，但更大数据应按账号、阶段、来源建立可索引查询与稳定游标 |
| P2 | 页面模块进一步拆分 | Dashboard、Discovery 及联系组件较大；按机会、沟通、分析、发送状态拆分 composable 与视图，减少交叉状态 |
| P2 | 资源体积与连续运行 | 网页路由已按需加载，但桌面主入口和总览 chunk 仍大；Element Plus 按需、图表延迟加载和连续 8 小时内存／监听器观察尚未完成 |
| P2 | HTTP 与启动细节 | 本机接口有来源和 token 校验，但通用请求体上限较大、缺乏全局速率控制；独立网页启动共用构建缓存文件也可改为原子发布 |
| P2 | 求职目标分组与对照复盘 | 保留硬条件，在不同岗位族下比较相关案例与真实推进数据；需足够样本、明确时间范围及分母，不能把未回复都归因为话术 |

猎聘实时接入、多城市自动采集、公交路线、Windows／macOS 完整发行继续保留未交付状态。本轮不为扩大范围增加新的收费地图或第三方搜索 API。

## 验证证据

- `pnpm check`：**281 项回归通过，0 失败**；Node／Vue 类型检查、正式网页、主进程、预加载与后台生产构建通过。
- Electron 本地协议隔离检查：**47 项通过**（10＋17＋6＋14），覆盖浏览器生命周期、账号／读取、联系双阶段与发现流程；不连接真实招聘者。
- 容量：隔离的 5,000 个岗位、50,000 条消息、5,000 个联系任务；每接口 25 次，P95：联系列表 6ms、联系汇总 56ms、机会列表 120ms、会话列表 53ms、消息页 26ms。这是本机服务调用，不含真实网络、HTTP 编解码和浏览器渲染；不是长时间负载测试。
- 正式网页资源的隔离 UI 验证：1280×720 和 1920×1080；推荐快捷定位、筛选空状态与恢复、详情证据展开、成果案例键盘展开、索要简历提示、任务阶段与队列数量。观测到的检查路径无浏览器控制台 error，页面没有文档级横向溢出。
- 独立审校测试覆盖“不带数字的虚构技能”、缓存命中不再调用、审校失败不写可发送缓存；队列测试覆盖默认提示词变化、资料变化、手动优先与历史结果失效；流测试覆盖已连接但无数据时取消。
- 本轮没有调用真实付费模型、没有发送真实消息，没有运行破坏生产端口或 BOSS 会话的客户端重启测试。真实内容质量、真实平台发送、0.18.1 完整启动升级以及连续运行仍需对应验收。

日志、隔离数据和修改前源码备份位于本机 `artifacts/system-review-20260921/`，不提交其中的私人备份或运行资料。旧 0.18.0 完整客户端启动验收见 [历史记录](VALIDATION_INDEPENDENT_20260921.md)，不能替代本轮未执行的部分。

完整包清单及哈希记录在 `artifacts/system-review-20260921/package.json`。退出客户端后，按 [安装完整包](OPERATIONS.md#构建与安装完整包)使用该文件中的发布目录和 `manifestSha256` 安装；旧发布目录保留。当前改动没有新增数据库 schema 迁移；旧代码仍使用既有库格式，但程序回滚不会自动撤销升级后新保存的个人资料或任务记录。

这次审查没有把既有未验收阶段改为已验收，也没有把模拟响应、已点击或已生成当作真实投递完成。
