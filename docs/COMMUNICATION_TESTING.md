# 招呼与回复测试及评审

此测试体系验证三件不同的事：程序是否正确控制生成和发送、模型是否忠实回答、接收者是否能理解。三类结果分别记录。模型“审校通过”不等于真人 HR 会认可，更不表示已经发送。

## 场景目录与标准

场景位于 `tests/fixtures/communication/cases.cjs`，共 50 项：

| 类型 | 数量 | 覆盖 |
|---|---:|---|
| 分流 | 32 | 问候及组合问候、城市、本人职责、项目工期、技术性能、未确认经历、谈薪、约面、简历、隐私、婉拒、不可信消息 |
| 表达规则 | 12 | 固定反问及变体、简单问题过度介绍、具体澄清、邀请提问、内部维护说明、HR 术语负担、技术追问、行业点评口吻 |
| 语义评审校准 | 6 | 项目用途、本人贡献、日活与累计用户、覆盖率与效率、未确认训练效果、越界承诺 |

合成数据只用于测试，不能导入真实简历或发送。真实话术测试使用本机只读快照、原资料版本和当前配置模型。两类输入在报告中明确标记。

评审分别给出以下七项结果，不计算录用概率：

1. **事实依据**：个人事实有已确认来源，数字保留主语、范围和口径。
2. **回答当前问题**：先回答对方所问，首次联系说清 JD 与经历的联系。
3. **可读性**：HR、业务或技术视角，必要术语符合问题，不粘贴无关内部说明。
4. **求职者角度**：不教企业做业务，不替对方断言痛点。
5. **信息量**：地点和问候短答，具体追问按需展开，不附固定反问。
6. **上下文衔接**：不重复自我介绍或索要已知信息；必要澄清和明确邀请提问可以保留。
7. **确认边界**：谈薪、约面、附件和隐私仍由本人确认。

每项只标记 `pass / fail / insufficient`，包含理由、逐字原文和经历引用；缺失内容单独标记。不存在的引文或未确认的经历 ID 会使评审无效。评审器不能改资料或发送消息。

## 离线检查

```bash
npm run test:communication
npm test
npm run eval:communication -- --out=artifacts/communication-offline-新的编号
```

`test:communication` 验证生产函数：事实与重要事项拦截、独立审校拒绝、限流不重试、取消、账号和资料变化、缓存失效、自定义提示词不能绕过表达检查等。

`eval:communication` 默认不联网、不读个人数据库。它输出分流结果、表达检查结果和评审标准。语义校准没有运行时不会标为通过。

退出码：`0` 表示本次指定检查通过；`2` 表示存在未通过、未完成或待复核项；`1` 表示测试工具自身无法运行。不要把“没有文本”“模型限流”“未运行”算成功。旧问题有真实失败记录，修复后应使用新报告目录复测，不覆盖旧报告。

## 真实生成与前后对比

显式 `--real` 才会调用配置模型并消耗额度。保留当前模型和 max 配置，不改生产模型设置。

```bash
node scripts/atlas-communication-evaluation.cjs --real \
  --only=reply-explain-ai,reply-location \
  --out=artifacts/communication-generation-新的编号
```

生成脚本目前包括本机选定的真实岗位案例；`--only` 可以只运行已选回复场景。真实岗位 ID 需要来自当前账号，缺失时停止，不能捏造公司或 JD。每个场景在本测试中最多等待 5 分钟，不改变生产的 45 分钟上限；限流后停止新增场景，不自动重试。

```bash
node scripts/atlas-communication-suite.cjs \
  --replay=artifacts/旧版本/results.json,artifacts/新版本/results.json \
  --only=reply-explain-ai,reply-location --judge-real \
  --out=artifacts/communication-review-新的编号
```

每次评审至多 8 条文本、1 次模型请求，不执行工具。按照生成时的 `profileVersion` 只读加载经历；原版本缺失时标记无法核实，不拿今天的简历替代。首次生成失败的记录保留为失败，不拿内部未通过的草稿当成功回复。

评审提示词位于 `scripts/lib/communication-review.cjs` 的 `judgePrompt`，可版本化修改。报告保存提示词哈希、原输入哈希、模型配置标识、耗时和用量，不保存密钥。它是测试进程的评审器，独立于业务 Agent 和发送调度。

## 检查评审器本身

```bash
node scripts/atlas-communication-suite.cjs --calibration --judge-real \
  --out=artifacts/communication-calibration-新的编号
```

6 条校准文本为明确标记的合成样本，包括正确回答及故意写错的指标、未确认成果和越界承诺。预期判定不提供给模型；程序收到结果后才核对。识别错误文本为失败才算该校准通过，不能把这些文本误算为产品生成失败。

同一个模型也可能宽松评审自己的表达，因此“独立调用”不代表独立模型或真人 HR。报告应结合确定性检查和内容复核；例如写了“通俗讲”不表示后续的 Skill、Agent 等术语已经解释清楚。

## 当前表达约束

- 规则回复不再附“方便介绍岗位职责和团队情况”等结尾。
- AI 回复也检查无必要反问与简单问题过度介绍；命中时保留草稿待核对，不能因模型审校说通过而直接发送。
- 首次招呼支持 `closing=none`；旧 `scope / priorities` 值不再追加问题。已有会话的匹配介绍不再强制附邀请。
- 表达检查不剪掉原文后偷偷发送，也不改动用户亲自确认的文本。
- 真实发送行为仍需平台执行器核验，本测试没有验证或触发真实发送。
