# 开源代码与本机私有配置

Atlas 的源码和用户配置分开。每位使用者安装后，在自己的电脑配置模型并登录 BOSS；项目不提供共享账号，也没有托管密钥的中转服务。

| 分类 | 位置 | 是否随源码或安装包发布 |
| --- | --- | --- |
| 界面、后台、模型适配器、Agent 代码 | 项目中的 `packages/` | 是 |
| 测试、配置说明与空值示例 | `tests/`、`docs/`、`.env.example` | 是；测试使用无效示例凭据 |
| 模型渠道、模型选择与 API Key | 数据根目录的 `private/models.json` | 否 |
| 简历、会话、机会、任务与附件 | 数据根目录的 `storage/`、`attachments/` | 否 |
| BOSS 登录 Cookie 与浏览器会话 | 数据根目录名称加 `-desktop` | 否 |
| 本机接口临时令牌 | `storage/atlas-runtime.json` | 否 |

默认数据根目录为 `~/.local/share/zhitu-atlas/`，可以使用 `ATLAS_DATA_ROOT` 指向仓库之外的绝对路径。私有配置和桌面会话目录拒绝位于 Git 工作区内部，也拒绝符号链接。不要把用户数据目录作为开源项目上传。

## 保存与调用

在「设置 → 模型」选择渠道和模型，输入密钥后保存。密钥通过本机会话接口交给后台；保存后清空输入框，读取设置时不会返回已保存的密钥。同渠道换模型可以留空继续使用原有密钥。

调用路径为：**网页或桌面 → 本机后台 → 本机私有配置 → 所选模型服务 → 本机工具执行 → 返回结果**。前端不直接携带模型 Key 请求服务商，也不从 `VITE_*` 环境变量注入凭据。内置渠道使用固定地址；自定义兼容地址由本人明确填写，密钥绑定完整地址，更换地址不复用旧密钥。所有渠道禁止重定向。

“本机调用”指调度、读取凭据和工具执行都在本机。选择 CommandCode 或 DeepSeek 时，模型推理仍在对应服务商执行，任务所需的简历、JD 或会话上下文会随请求发送；这不是离线推理。

BOSS 通过自己的登录页面建立本机会话，Atlas 不额外收集或保存 BOSS 明文密码。Git／SSH 的账号密码也不属于项目配置，不写入源码或部署脚本。

## 旧配置迁移

新版首次读取模型配置时，将本机 `config/llm.json` 迁到 `private/models.json`，保留已选模型、渠道及密钥。迁移采用本机写锁、临时文件、落盘和回读校验，校验通过后才删除旧配置文件。

- 中断后重新读取会继续核对，内容一致时完成清理。
- 新旧内容冲突或 JSON 损坏时保留文件并报错，不静默覆盖、重置或打印原文。
- 同机多人或多个窗口保存时检查配置版本，过期编辑不会覆盖新值。
- 请避免新旧客户端同时改模型配置。旧客户端只认识旧路径；回滚到旧版若需要凭据，应在退出新版后从本机迁移前备份恢复，不能把私有文件拷回源码仓库。

私有目录权限为 `0700`，文件为 `0600`。这是本机文件权限隔离，**不是加密保险库**；同一系统账号及管理员仍可能读取，因此不要共享系统账号或公开整个用户目录。

## 备份与开源检查

界面导出的加密迁移备份包含业务数据和附件，不包含 `private/`、BOSS 会话及模型密钥；新电脑需要重新配置凭据。原始数据库、手动整目录备份和历史安装副本仍属于私人文件，不能当成开源附件。

```bash
pnpm check:public
pnpm check:public:history
pnpm check
```

第一条检查 Git 跟踪及未忽略的新文件；第二条同时检查本地可达 Git 历史；第三条包含回归、类型和生产构建。构建和打包也检查产物，拒绝私有配置、数据库、简历及疑似凭据。报告只输出文件位置与规则，不输出密钥。检查采用有限的规则，不能代替发布前对新增截图、文档及附件的人工审查。

`.gitignore` 防止常见私人文件意外进入 Git，但不会自动删除已经提交过的文件。历史检查失败时应先核实，再分别处理密钥轮换和历史清理；不要只修改最新文件就宣称历史已清理。

## 地图配置

0.22.1 的天地图 Key 单独存放在 `private/maps.json`，与模型凭据同样使用本机私有目录、原子保存和版本冲突检查。前端读接口只返回是否配置，不回传 Key；业务备份不包含此文件。新电脑需重新配置，已有企业坐标与通勤起点保留。
