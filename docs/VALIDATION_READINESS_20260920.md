## 问题与修复

| 环节 | 问题 | 最终行为 |
| --- | --- | --- |
| 学历匹配 | 非全日制可能被子串识别为全日制；岗位学历字段可能掩盖 JD 更强要求 | 同时检查字段与必须项；非全日制不满足全日制要求，学习形式未知进入待核实 |
| 经历匹配 | 通用产品年限不能证明 AI 专项年限 | 通用年限和 AI 年限独立核实；不自动补全 |
| 薪资 | 低于底线的原因文案仍可能写成区间符合 | 明确说明薪资上限低于期望；符合区间不代表薪资承诺 |
| 分析时效 | 过期原因笼统；列表和执行入口对缺失地址使用不同默认值 | 分别提示资料、JD、模型／渠道／提示词变化；统一岗位字段默认值 |
| 推荐数量 | 推荐卡、列表与统计使用不同筛选范围 | 共用推荐条件，排除已跟进、已拒绝、不相关、结束及已推进记录 |
| 联系授权 | 自动联系未沿用逐条确认要求 | 生成后持久化为待本人确认；发送前再次验证具体文本、账号、招聘者、岗位、资料与分析版本 |
| 暂停期间准备 | 必须运行发送流程才能准备首次联系话术 | 详情页可独立后台准备话术，不取得浏览器能力，不解除发送暂停 |
| 模型失败 | 自动发现的分析中断可能显示整轮完成 | 保留已完成步骤，停在分析阶段等待处理 |
| BOSS 稳定性 | WebContents 销毁期间可能访问空对象；页面脚本读取可能无限等待 | 销毁前解除引用，完整检查对象与窗口；原生联系读取限时 15 秒 |
| 额度说明 | 本机每日限制可能被误解为 BOSS 官方限制 | 明确区分；平台额度未知不猜测。观察到当天开聊额度耗尽提示后停止该账号新增联系，不影响已开聊任务的匹配说明 |

## 发送流程

1. 统一匹配通过后准备话术，模型生成与事实审校完成后进入待确认。
2. 弹窗显示完整文本与依据。本人勾选并确认后才允许排队；关闭、复制或生成均不是发送。
3. 确认绑定正文和来源版本。跨窗口冲突、内容变化或来源失效时不继续发送。
4. 发送暂停、运行时段、消息限额、首联限额、冷却、账号与会话检查仍独立生效。
5. 平台默认招呼只算已开聊；个性化文本和消息标识回读一致才算联系完成。结果不确定不重放。

原本的本机发送限额保留。没有以网络文章中的通用数字代替当前账号额度，也没有购买平台权益或以测试消息探测上限。

## 升级与回滚

1. 退出客户端及对应守护进程，保留当前数据备份。
2. 使用 `scripts/atlas-install.cjs` 及已核验 SHA-256 安装构建的归档；安装工具保存上一个归档。
3. 如需回滚，退出应用后安装此前保存的 `app.asar.backup-<hash>`，传入该文件的实际校验值。
4. 本轮没有新增数据库表。一般代码回滚不回退业务数据；只有确需恢复数据时才使用已核验备份，以免覆盖升级后的编辑。
5. 回到旧版前保持发送暂停：旧版不包含本轮新增的逐条话术确认门槛。

本机私有证据位于 `artifacts/readiness-20260920/`（Git 忽略）。它包含资料和平台信息，不应上传仓库或作为公开测试样本。
