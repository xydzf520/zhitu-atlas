# 0.21.2 工程配置、路由与历史导入重写

本次针对上一轮核查后仍沿用的配置、重复路由及历史兼容代码重写。岗位匹配、模型网关、发送规则与已有 Atlas 执行链继续使用现有实现，不宣称重新编写了整套应用。

## 工程与编译

- 原来与上游基线相同的 8 份配置已重新建立或删除。格式规范、忽略规则放到项目根目录；Markdown 保留有意义的尾随空格，生成产物和本机数据继续排除。
- 工作区明确限定 `packages/ui`；依赖安装使用统一锁文件，并检查运行环境版本。
- 增加自有 `tsconfig.base.json`，Node 和网页继承同一检查规则；明确 ES2022 目标及 Bundler 模块解析，网页入口本身也进入类型检查。
- 移除 `@electron-toolkit/tsconfig` 模板依赖。Vue、Electron 等通用组件和它们的许可仍然保留。

## 一套路由

桌面和网页都使用 `createAtlasRouter`。页面组件、标题、旧书签跳转以及任务和同步入口在同一处维护。旧路径只是输入数据，不用于动态拼接组件或执行模块。

跳转保留账号等查询条件和锚点，只替换必要的目标筛选。页面标题以实际页面为准，例如发现页携带 `view=companies` 不会被错误标成“企业与进展”。连续访问指向同一页面的不同旧书签时也会归一地址；只处理重复导航，不绕过未保存草稿的取消操作。

## 重新实现历史导入

删除原 `atlas-unify-data.ts`，使用 `atlas-history-import.ts`：

1. 以只读事务读取原始数据库的一致快照，不调用模型或招聘平台。
2. 建立账号、企业、岗位和招聘者索引，按明确账号关联历史记录；未知或冲突归属留在原始档案。
3. 逐条保存档案；同一来源 ID 的不同内容均保留。冲突消息不会被当成唯一正确内容导入会话。
4. 会话摘要按消息时间选择最新记录。一个招聘者关联多个岗位时保留候选列表，不跨账号取第一个岗位。
5. 目标库在一个事务内提交，失败整体回滚；完成标记在事务内再次检查，多进程不重复导入。
6. 已存在的岗位、消息、会话、人工备注和发现状态优先，不被历史数据覆盖。

旧版本已经完成的导入保留原完成标记，升级不会自动重放、修复或覆盖已导入的数据。原始档案保留；需要修复历史数据时应单独核对。

旧筛选条件仍由 Atlas 当前策略服务解释，未知条件继续进入待核实。没有当前调用方的 `career-profile-legacy` 和 `career-policy-import-legacy` 接口已移除；资料和策略均通过带版本校验的统一入口保存。

## 验证范围

- 迁移专项：账号隔离、乱序消息、多岗位招聘者、未知归属、冲突 ID、已有数据保护、失败回滚、重入、多进程及链接路径。
- 路由专项：全部保留书签、查询条件和锚点、任务与同步入口、标题和异常路径。
- 隔离规模：5,000 个岗位、50,000 条消息，导入约 1,549 ms；20 次“历史申请＋归档读取”组合查询 P95 约 31 ms，进程最大 RSS 239 MiB。该指标来自本机合成数据，不代表平台网络请求耗时。
- 逐文件比对：以核查基线 `c4ebdb0882d8dbecfd9864f980f6d13bd1eb4b2a` 比较当前非忽略文件，完全相同项为 0；不据此抹去历史来源或宣称所有思路均从零创造。

最终结果：**477 项回归通过，0 失败、0 跳过**；Node／Vue 类型检查、网页与桌面生产构建、依赖图和私有数据扫描通过。另完成 8 项模型设置页面检查和 10 项生产网页路由检查，页面无异常；149 个文档本地链接无缺失目标。模型检查使用模拟服务，未产生真实模型调用。
