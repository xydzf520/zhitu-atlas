# 使用指南

适用：职途 Atlas **0.21.0**。目标是找到合适岗位、说明经历与岗位的联系，并把真实进展记录清楚。

## 先把资料和规则准备好

在「简历与资料」保存简历全文、个人定位与优势、AI 可引用经历、学历与资历。全文和经历证据属于同一份带版本资料，但分别编辑：修改证据不会自动重写简历全文，反之也不会自动确认经历。Word 导出使用本机简历正文；仅用于匹配的资历不自动加入正文。

只有本人已确认的经历才能用于自动联系。数字、职责和项目成果应有来源；公开代码能力不能直接写成业务成果。经历关联 GitHub 项目时，分别确认个人贡献和公开仓库状态。仓库核实有效期 24 小时，公开元数据核实不能代替贡献确认。

本地保存不等于 BOSS 在线简历已更新。需在平台保存并重新读取核对；当前工作台不提供所有资料字段的无人值守自动同步承诺。

在「机会发现」保存求职方向、城市、薪资、核心关键词和排除条件。现有用户可以保留自己的原策略；**全新安装不预填个人经历或薪资**。岗位上限达到期望只表示区间有空间，例如期望 40K 时 30–50K 可以评估，不代表企业承诺 40K。

在「设置 → 模型与 AI 用量」配置模型。操作及付费测试说明见 [模型与工具](COMMANDCODE.md)。

## 登录、发现与联系

1. 在桌面「BOSS 工作台」登录。内嵌页面和应用打开的独立 BOSS 窗口共享会话；普通 Chrome 或 Codex 浏览器的登录不等于桌面已登录。
2. 打开消息或岗位页面后，到「任务中心」查看账号核实、已读取范围与缺失字段。同步只代表已采集到的内容，不能据此判断全部历史都已同步。
3. 在「机会发现」选择「目标岗位搜索」「BOSS 推荐岗位」，可以单选或同时启用；浏览采集及导入也进入候选池。
4. 先查看匹配依据、缺口及待核实项。资料未确认、薪资未知、招聘者身份缺失、JD 不足或分析过期时，按阻塞原因处理。
5. 选择「仅挖掘岗位」或「匹配后自动联系」。自动联系还可选择匹配及事实校验后自动发送，或逐条确认；点击对应启动按钮才创建授权与任务。
6. 在联系结果中查看实际消息、时间、回读凭据、失败原因和下一步。需要追问、发简历或确认重要事项时转到「沟通中心」及 BOSS 页面处理。

同一账号的同一岗位按平台来源 ID 去重，多来源保留记录；同一招聘者多个岗位不重复首次介绍。已有会话转入沟通，同公司不同招聘者可分别联系。名称相似不自动合并。

岗位详情先看投入建议及「用人视角」：HR 必要条件、岗位业务目标、你的下一步。展开成果案例，按“背景与目标 → 本人行动 → 结果与证据 → 边界与复盘”准备回答；待核实问题用于向招聘方确认。它们来自当前分析和本人确认的证据，不是招聘方已承诺的职责或录用意向。逐项证据矩阵和长报告可以继续展开。

机会发现的策略编辑、联系漏斗和执行明细默认折叠，顶部保留授权、额度和异常提示。点击联系指标或来源筛选会展开对应结果。BOSS 搜索按已保存的目标城市生成入口；多城市共用每日候选、详情、分析和发送额度。地点不明或与目标城市不一致时，保持待核实或排除。

## 自动化怎样受控

新安装自动任务和发送保持暂停，自动推荐关闭，需本人明确启用；已有设置保持不变。

以下为程序策略初始值，迁移后的实际值以界面保存的策略为准；这些是 **Atlas 本机额度，不是 BOSS 官方账号额度**。

| 项目 | 初始值或规则 |
| --- | --- |
| 每日主动发现 | 最多 60 个去重候选、40 份详情 |
| 自动岗位分析 | 每日最多 30 次生成请求；工具续轮也计次数，因此不保证完成 30 份报告 |
| 自动策略复盘 | 每日最多 1 次生成请求 |
| 每日推荐时间 | 北京时间 09:30，程序在运行且账号有效时执行；21:00 前可补一次 |
| 自动消息／首次联系 | 默认每日 20 条自动消息、10 次首次联系；平台默认招呼也计消息额度 |
| 发送时段与频次 | 北京时间 09:00–21:00，同会话至少间隔 10 分钟，24 小时最多自动沟通 3 次 |
| 重要事项 | 简历附件、正式申请、薪资承诺、面试确认由本人处理或确认 |
| 结果不确定 | 不自动重发；先选择已发送／未发送／仍不确定，重新排队须明确操作 |

自动匹配同时检查岗位方向、实际城市、薪资、JD、招聘者、必要资历、已确认经历、最新 AI 建议与发送条件。内部初筛 65 分只是一项门槛，不是录用概率；缺少硬条件时，关键词命中再多也不会自动联系。

平台若先发送默认招呼，任务会预留两条消息额度，等待冷却后补发个性化说明。只有后者经回读核验才完成自动联系。等待期间招聘者回复、本人输入或依据变化，会转为待处理。

「暂停发送」保留同步与分析能力；「暂停全部自动任务」阻止新的自动步骤，手动请求的分析仍可运行。暂停不撤回已发出的消息，也不保证已经发出的网络请求立即消失；本人正常浏览已打开页面时，被动归档仍可能保存页面中观察到的资料。退出桌面后不会继续执行 BOSS 浏览器操作；没有外部常驻调度器替你唤醒电脑。

## AI 话术与自动回复的区别

- **首次联系**：结合完整 JD、已确认经历和岗位分析生成，再独立核对事实。使用机会发现里保存的自动／逐条确认授权；不匹配或校验失败时不发送通用介绍代替。
- **沟通中心手动生成**：完成后弹窗阅读和确认。确认保存、编辑或复制只处理草稿，不等于发给招聘者；提交发送指令仍受单独的发送控制。
- **常规自动回复**：先经过规则分类。配置模型时，结合已同步文本生成，再独立审校事实、相关性和承诺；任一步失败保留待确认草稿。每次非空新回复通常包含生成、审校两个模型阶段，分别计量；缓存命中不重复调用。未配置模型时，部分已支持的简单咨询可以使用确定性规则回复，不能把所有回复都称为 AI 生成。
- **企业研判**：只读搜索和分析；首次生成后可开启新回复修正，不修改投递资格，也不发送消息。

沟通中心的下一步根据已同步文本变化：索要简历时先准备材料，询问面试或薪资时由本人确认，自己刚发过消息时先等待，明确婉拒时记录原因并由本人决定归档。未回复不能推断为拒绝，索要简历不能当作面试邀请；资料未同步完整时先查看 BOSS 原文。

任务排队期间若资料、策略、模型或提示词变化，旧任务会中断并说明未调用模型，需要按新依据重新创建。手动请求优先于尚未开始的自动任务，但不会打断正在生成的模型请求。默认提示词随版本更新也会使相关旧分析失效，历史报告仍可阅读。

## 每个页面负责什么

| 入口 | 主要用途 |
| --- | --- |
| 全景总览 | 查看阶段分布、地区分布、推荐和待处理事项 |
| 全局分析 | 查看资料准备、岗位样本、竞争力诊断、市场研判和改进项 |
| 机会发现 | 获取岗位、看匹配、选择授权、启动联系、查看数量与结果 |
| 企业与进展 | 管理已关注／联系机会，查看看板、联系人、面试与 Offer |
| 沟通中心 | 读取已同步消息、生成话术、处理待确认和跟进、查看企业研判 |
| BOSS 工作台 | 登录和平台原生操作；仅桌面提供内嵌浏览器 |
| 简历与资料 | 维护正文、优势、证据、资历、项目和版本 |
| 任务中心 | 查看执行步骤、同步覆盖、额度、暂停和异常结果 |
| Agent 管理 | 查看和修改业务提示词、启停、历史与调用记录；不能解除发送规则 |
| 设置 | 模型、用量、存储管理、文件导入、加密备份、连接信息和迁移档案 |

## 数量和地图怎么看

| 状态 | 含义 |
| --- | --- |
| 新发现／匹配通过 | 新增去重岗位／满足当前联系检查；均不代表已发送 |
| 待联系 | 已入队但尚未开始平台联系动作的当前库存 |
| 已开聊 | 建立了会话，匹配说明可能尚未发送 |
| 自动联系成功 | 实际个性化说明及消息标识已经平台回读核验 |
| 人工确认已发送 | 由本人确认，和平台核验分开计数 |
| 简历已投递 | 应对应实际附件或申请凭据，不能由开聊次数推算 |
| 消息数 | 默认招呼、个性化说明和自动回复等消息数量，不是企业数量 |

同公司联系两位招聘者，可对应两条机会、一家企业。今日新增、当前待处理库存、指定期间的同批联系进度，统计分母不同。手动调整阶段只记录进展，不会自动发送消息，也不能凭阶段标签证明平台已投递。

地图使用同一机会数据。只有具备明确 WGS84 坐标的记录展示精确点位；区级位置按区域汇总，未知位置保留待补充。直线距离不是通勤时间；通勤分钟数和备注由本人记录。在线底图加载失败时仍可查看本地区域分布。

遇到连接、缺失数据或任务问题，先看 [运行与排错](OPERATIONS.md#常见问题)。


## 全局分析

左侧「全景总览」下进入「全局分析」。先看资料准备、优先处理和岗位样本图表，再按需点击简历或市场卡的「开始分析」。使用设置中已保存的渠道与模型，产生模型用量；切换页面后任务继续，可在任务中心取消。相同依据复用缓存；需要更换分析方法可在 Agent 管理修改提示词后更新研判。

- 简历竞争力：从 HR 对履历、层级和事实的核对，以及业务部门对判断、交付、协作和结果的关注评估整份经历。
- 市场机会：比较当前账号已采集岗位的方向、城市、薪资、业务需求与个人依据。没有外推全国人才供需或竞争者数量。
- 图表来自真实记录。资料准备环图不是竞争力打分；薪资按有效月薪区间中点统计，未知值单列。窗口按最近观察时间，不是岗位发布时间。
- AI 默认阅读窗口内最近 60 份去重岗位的 JD 摘要，同时使用整个窗口的统计；个人优势要求引用已确认经历，机会结论要求引用岗位。
- 点开依据查看来源，点击建议跳到相应资料或岗位页面。建议不会自动改简历、确认经历、调整硬条件或发送消息。
- 资料、岗位、模型或提示词变化后，旧报告标为过期；失败保留原报告。两个新增 Agent 可分别编辑、启停和查看实际调用记录。

## 全国地区视图

总览默认汇总实际记录中的城市，点击城市展开区县，并联动统计及列表。没有地址的机会仍保留在「地点待核实」。已有上海用户的求职偏好不变，新安装不预设个人城市。

「区域分布」不联网也可查看数量；「街道地图」按当前视野加载 OSM 底图，只显示已确认的 WGS84 坐标。其他坐标系、区域定位不会伪装成企业办公点；直线距离不表示通勤时间。

## 全国机会地图

全景总览和企业与进展中的地图可选择全国或具体城市。首次进入采用求职策略的首选城市；点击“当前城市”可随时返回。全国按城市汇总，点击圆点进入城市；城市内区分已确认 WGS84 位置和区县汇总，颜色表示求职阶段。没有地址的机会保留待核实，不生成坐标。

底图使用 DataV / 高德中国地图，全国完整保留台湾省和南海诸岛、断续线。“街道底图”加载失败时显示同一份本地区域轮廓，地图仍可缩放、查看岗位。离线地图不含道路详情。通勤起点由本人点选保存，地区汇总点不参与企业精确距离计算。

## 今日求职安排

在全景总览地图下查看「今日求职安排」。默认「只给建议」，按最新沟通、近期面试、匹配联系、岗位分析及资料改进排序。每项有原因、状态和对应页面；「执行记录」保留失败、中断和已提交的结果。

点击「AI 调整安排」会创建后台模型任务，每日最多 2 次，手动与自动共用预算。可以切换页面、取消任务；失败保留原安排。Agent 管理中的「求职协调」可以修改提示词、停用或查看调用记录。

选择「自动安排」后，程序在 09:00—21:00 逐项提交现有模块；全局暂停仍然生效。它不会解除发送暂停、确认经历或修改求职城市与薪资。自动联系只有在机会发现中已经授权、匹配与事实校验通过时才进入原发送队列。每日额外安排最多 6 项企业、面试、简历或市场辅助分析；岗位分析继续使用既有 30 次预算。

沟通卡上的「已处理」只隐藏这一版消息的提醒，新消息会再次出现，不代表已读或已发送。结果页按近 7 天创建的同一批联系任务追踪，模块完成、人工确认和平台核验分开显示。失败或依据变化的任务请进入对应页面核实后重建，不自动重放。


## 看 Agent 正在做什么

打开「任务中心 → Agent 运行台」。左侧选择岗位或会话，中间选择实际步骤，右侧查看结果、经历依据或运行记录。总览、机会发现、沟通中心及 Agent 管理的“查看工作进度”都进入同一份记录。

协调安排完成不代表子任务已完成；话术生成不代表已发出。模型候选话术、通过检查的结果及平台发送凭据分别标注。重要事项仍在原会话中确认，点击“编辑草稿 / 处理事项”返回。

“暂停本条流程”只阻止这条流程后续步骤；“暂停发送”与“暂停全部自动任务”保持独立。取消不能撤回已发送消息。需要重新生成时，可以填写本次表达要求并确认新调用；原结果保留，全局提示词和个人经历不被改写。

旧版本未记录的父子关系不会猜测补齐，旧记录仍可在执行队列和 Agent 调用历史查看。完整说明见 [Agent 运行台](AGENT_WORKBENCH_021.md)。

## 开始使用与虚构示例

总览在资料未准备好时显示清单，设置的「开始使用」页随时可打开。资料和方向是本机基础；AI 和 BOSS 连接按需配置，也可通过文件导入管理机会。示例使用虚构履历，只有本页面的匹配与规则草稿展示，不入库、不调用模型、不触发任务或发送。
