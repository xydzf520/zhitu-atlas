# 求职协调 Agent · 0.20.0

## 交付内容

全景总览地图下新增「今日求职安排」，提供下一步、执行记录、联系结果三个视图。重要沟通和近期面试优先，其次推进匹配岗位、补充样本、改进资料与搜索策略。Agent 管理增加「求职协调」，可修改提示词、启停并查看实际调用。

协调器复用搜索、JD 分析、首次联系、企业研判、面试准备、简历和市场研判、策略复盘模块。回复继续走现有沟通中心和自动回复规则；协调器不另建回复或发送引擎。

## 决策与执行

1. 程序根据当前账号、资料、JD、会话及策略生成有限候选。
2. 默认显示规则安排；请求 AI 时，模型仅可选择候选 ID 和同优先级内的顺序。
3. 程序保留重要事项，验证模型输出，并在执行前再次核对依据。
4. 使用原任务队列提交模块工作，持久记录任务 ID、版本、状态与原因。
5. 模块结果与平台发送凭据分开；失败、中断或不确定结果不自动重放。

模型不能创建任意工具参数，不能调用会解除暂停的 `startContacts`，不能更改城市、薪资、经历确认、发送授权和额度。自动联系只在既有授权与资格通过时入队，平台核验仍由原执行器完成。

默认「只给建议」。打开「自动安排」不会解除全局暂停或发送暂停。在 09:00—21:00，每分钟检查一次，手动任务及已有队列优先。AI 安排每天合计最多 2 次，手动和自动共用；自动安排每天最多请求一次规划，失败后继续使用规则安排。额外企业、面试、简历与市场分析每天合计最多安排 6 项，岗位分析、读取及发送继续受原预算约束。所有额度和幂等记录保存在 SQLite，刷新或重启不重置。

沟通的「已处理」只记录本人对该版本消息的处理，不当作消息发送、已读或面试凭据；收到新消息后重新提醒。近 7 天联系结果使用同一批创建的联系任务，单列平台核验与人工确认，不提供录用概率。

## 数据及边界

- 继续使用 schema 6，新增 `atlas-coordinator-*` 文档，不改写旧资料或发送记录。
- 备份保留配置、安排和执行记录；恢复后关闭自动安排、暂停全部任务并中断在途步骤。
- 每次最多检查当前账号最近 120 个岗位、30 个会话；界面说明样本范围，不宣称覆盖整个招聘市场。
- 失败或输入变化后需在对应模块核实并重新创建任务。同一依据的失败行动不因自动刷新而重放付费请求。
- 真实平台投递仍需对应账号、岗位和消息的实际验收。本轮没有发送测试消息，也没有将单元测试当作真实投递成功。
