# 0.18.2 存储升级与验证

日期：2026-09-21。范围：业务存储、查询、备份恢复与设置界面。本轮没有调用付费模型或给真实招聘者发送消息。

## 已交付

| 改动 | 行为与边界 |
| --- | --- |
| 分析正文复用 | `analysis_contents` 按正文内容哈希保存不可变正文；分析缓存、岗位记录和任务引用正文，各自保留账号、资料版本、模型及证据元信息。读取接口还原原有业务结构。 |
| schema 6 | 迁移与版本记录在同一事务内提交；失败回滚，可重复检查。新增文档族、任务、岗位和机会关联索引及来源变更版本。 |
| 列表查询 | 来源未变时复用派生缓存，SQLite 完成筛选、计数与分页。源数据变化、账号或资料切换后重新计算；跨进程写入由数据库触发器使缓存失效。 |
| 岗位读取 | 去掉已采集岗位读取的 5,000 条截断；不更改跟进清单既有的 5,000 项上限。 |
| V2 加密备份 | 一致性数据库快照、托管附件和兼容旧档案，按 1 MiB 分块压缩与 AES-256-GCM 加密。每块绑定顺序，清单记录文件大小和 SHA-256，必须收到最终结束块。 |
| 恢复 | 先核对密码、格式、完整性、引用与外键；附件进入新的版本目录，数据库事务成功后切换引用。恢复后自动执行暂停，不重放结果不确定的发送。 |
| 存储管理 | 设置 → 数据管理 → 存储管理，展示占用、记录数、分析复用、上次界面导出记录，支持数据检查及限定范围整理。 |

## 备份限制与维护边界

- V2 原始数据总量上限 **512 MiB**，传输文件上限 **514 MiB**，单个托管附件上限 **15 MiB**，附件不超过 1,000 个。本轮实际恢复验证为 45 MiB 附件，并未压测到 512 MiB 极限。
- 服务端分块处理；浏览器下载仍需组装 Blob，因此大文件仍有浏览器内存开销。旧 V1 文件可读取，兼容导出接口仍保留旧限制。
- 首次读取或数据更新时，岗位匹配和排序仍会构造全量派生模型；不是完全流式查询。后续优化可把更多稳定字段结构化入库，但不能因此另造一套匹配规则。
- “整理”只删除没有现存记录引用的分析正文，以及超过 24 小时且未使用的备份临时文件，包括异常退出遗留的临时明文目录。保留聊天、投递凭据、报告引用、资料版本与业务历史。
- 在线整理做被动 WAL 检查点和索引统计维护，空闲页供未来写入复用，不在运行时自动 VACUUM。不能手动删除正在使用的 WAL。
- 旧安装包和项目构建产物保留，以供回滚；本轮没有用删除旧业务历史来缩减占用。
